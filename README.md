# To-Do List (Monorepo)

A full-stack to-do app. The repository is an **npm workspaces monorepo** with two packages:

| Package   | Folder    | What it is                                  | Docs                         |
| --------- | --------- | ------------------------------------------- | ---------------------------- |
| `client`  | `client/` | React + Vite frontend (shadcn/ui, Tailwind) | [client/README.md](client/README.md) |
| `server`  | `server/` | Express + MongoDB REST API                  | [server/README.md](server/README.md) |

```
todo/
├── package.json     root: workspaces + scripts
├── client/          frontend (package name: client)
└── server/          backend  (package name: server)
```

## Prerequisites

- Node.js 20 or newer (recommended) and npm 7 or newer (workspaces support)
- A MongoDB database, either [MongoDB Atlas](https://www.mongodb.com/atlas) or a local install (see the server README for connection details)

## Quick start

1. **Install everything once, from the repository root.** This installs the dependencies of both apps and the root tooling (`concurrently`) into a single `node_modules` and a single lockfile:

   ```bash
   npm install
   ```

2. **Create the two environment files** (they are not committed):

   ```bash
   cp server/.env.example server/.env
   cp client/.env.example client/.env
   ```

   On Windows (cmd), use `copy` instead of `cp`.

3. **Edit `server/.env`** and set `MONGODB_URI` to your real connection string. Leave `client/.env` as is unless your API runs on another port (`VITE_API_URL=http://localhost:5000/api`).

4. **Start both apps together:**

   ```bash
   npm run dev
   ```

   - Frontend: <http://localhost:5173>
   - API: <http://localhost:5000/api> (health check: <http://localhost:5000/api/check>)

   Output from both apps appears in one terminal, labelled `server` and `client`.

## Root scripts

Run these from the repository root.

| Command         | What it does                                              |
| --------------- | --------------------------------------------------------- |
| `npm run dev`   | Runs the API and the Vite dev server together             |
| `npm run build` | Builds the frontend into `client/dist/`                   |
| `npm start`     | Starts the API once (production-style, no file watching)  |

## Working with a single package

Use the `-w` (workspace) flag, always from the root:

```bash
npm run dev -w server          # run only the backend
npm run dev -w client          # run only the frontend
npm install axios -w client    # add a dependency to the client only
npm install express -w server  # add a dependency to the server only
npm install -D some-tool       # add a dev tool for the whole repo (root)
```

Do **not** run `npm install` inside `client/` or `server/` separately. Doing so creates extra lockfiles and `node_modules` folders that fight with the root install.

## Environment files

| File             | Used by | Key variables                                                       |
| ---------------- | ------- | ------------------------------------------------------------------- |
| `server/.env`    | API     | `MONGODB_URI` (required), `PORT` (default 5000)                      |
| `client/.env`    | Vite    | `VITE_API_URL` (must include `/api`, no trailing slash)              |

Each app reads its `.env` from its own folder. Vite only reads `client/.env` at startup, so restart `npm run dev` after changing it. `.env` files are git-ignored: never commit real credentials.

## Troubleshooting

- **`MONGODB_URI is missing`**: `server/.env` doesn't exist or lives in the wrong folder. It must be `server/.env`, not the repo root.
- **Frontend shows no tasks or "Network Error"**: the API isn't running, or `VITE_API_URL` points to the wrong address. Check <http://localhost:5000/api/check>.
- **Atlas connection times out**: add your IP address under Network Access in Atlas.
- **Install errors or odd duplicate packages**: delete every `node_modules` folder and any `package-lock.json` inside `client/` or `server/`, then run `npm install` again at the root.
- **Port already in use**: stop the other process, or change `PORT` in `server/.env` and update `VITE_API_URL` to match.

## Notes

- The frontend UI is built with [shadcn/ui](https://ui.shadcn.com); which files were generated by its CLI is documented in `client/README.md`.
- CORS is currently open to all origins and there is no authentication. See the server README for the full list of limitations before deploying anything.
